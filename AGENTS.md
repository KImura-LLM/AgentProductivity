# AGENTS.md

Минимальные рекомендации для дальнейшей разработки AgentProductivity.

## Принципы

- Сначала читать `PRD.md`, затем проверять текущую реализацию в `src/productivity_agent`.
- Держать изменения маленькими и проверяемыми: одна новая возможность — один понятный слой сервиса и тест.
- Не переносить бизнес-логику в Telegram handlers. Handler должен только принять сообщение, проверить авторизацию и вызвать `ProductivityService`.
- Считать `NormalizedTask` внутренним контрактом проекта. Коннекторы должны приводить внешние API к этой модели.
- LLM использовать только для формулировки и рекомендаций. Источником фактов остаются Notion, TickTick и локальный `ProductivityAnalyzer`.

## Safety

- Любая операция записи должна идти через pending action и явное подтверждение пользователя.
- При неоднозначном fuzzy match сначала показывать варианты и ждать номер.
- Не логировать и не печатать токены, ключи, OAuth-коды и содержимое `.env`.
- Если один источник упал, отвечать по доступным данным и коротко назвать недоступный источник.

## Архитектура

- `connectors/` — только API конкретных источников и маппинг в `NormalizedTask`.
- `repository.py` — объединение источников, поиск кандидатов, выбор нужного коннектора.
- `services.py` — сценарии команд, подтверждения, эффективность, orchestration.
- `analyzer.py` — deterministic scoring и fallback без OpenRouter.
- `llm.py` — компактный payload и русскоязычная генерация без технических деталей.
- `bot/app.py` — Telegram-команды, авторизация и расписание.

## Проверки перед завершением задачи

```bash
pytest
ruff check .
agent-productivity-cli doctor
```

Если изменение касается только документации, достаточно проверить читаемость markdown и отсутствие секретов.
